# BingX 실거래 봇 (live / $1050)

`Bingx_bot_certain`(페이퍼)에서 검증된 전략 엔진을 **실제 BingX 주문**으로 돌리는 인스턴스.
페이퍼 봇과 코드 대부분을 공유하되, 주문 집행 계층(`paper_trader.py`의 `_live_*`,
`bingx_api.py`)과 자본/리스크 설정만 실거래용으로 분리돼 있다.

## 실행

```bash
pip install -r requirements.txt
cp .env.example .env        # BINGX_API_KEY / BINGX_SECRET_KEY 채우기
python main.py              # 메뉴 시작
```

무창(백그라운드) 기동 — 워치독이 봇을 감시·자동재시작한다:

```powershell
powershell -ExecutionPolicy Bypass -File .\start_silent.ps1
```

긴급 전량 청산:

```bash
python close_all.py
```

## 손실 분석 (`analyze.py`)

`state.json`의 `closed_trades`는 최근 200건에서 잘려 학습 이력이 소실되므로,
청산 시마다 `trades.jsonl`에 한 줄씩 **영구 기록**한다. 기록에는 매매 판단에
쓰이지 않는 계측값이 함께 담긴다.

- **MFE** — 보유 중 최대 유리 지점. 손실 거래의 MFE = *놓친 익절*
- **MAE** — 보유 중 최대 불리 지점. 익절 거래의 MAE = *손절선을 조이면 죽었을 폭*
- **단계 이력** — DCA 각 단계의 시각·체결가·투입금·발동 사유(가격/횡보)

```bash
python analyze.py             # 전체 리포트
python analyze.py --days 7    # 최근 7일
python analyze.py --json      # 기계 판독용
```

리포트는 청산사유·DCA단계·코인·방향·시간대별 손익 귀속, 손익분기 승률,
그리고 손절 한도 후보별 총손익 스캔을 출력한다.

### 과거 기록 가져오기 (`import_history.py`)

다른 PC 의 모의투자 기록, 다른 봇의 `state.json`, 옛날 `bot.log` 를 저널로 합친다.
원본 파일은 건드리지 않는다.

```bash
python import_history.py ~/기록폴더 --tag paper --dry-run   # 먼저 확인
python import_history.py ~/기록폴더 --tag paper             # 실제 반영
python analyze.py
```

지원 형식: `state*.json`(closed_trades 배열) · `trades.jsonl` · `bot.log`(청산 줄).
`state*.json` 과 `.bak` 에 같은 거래가 중복돼 있어도 알아서 걸러낸다.

**MFE 역산** — 구 기록에는 실시간 계측값이 없지만 `peak_price` 가 남아 있어
"보유 중 최고 수익"을 되살릴 수 있다. 두 경로를 쓴다.

1. `total_invested` 가 있으면 (90win 계열): `투입 × 유리변화율 × 레버리지`
2. 없으면 (슬롯형): `pnl`·`비용`·가격으로 **수량을 역산** — 레버리지를 몰라도 정확하다

> `peak_price` 는 DCA 때마다 리셋되므로, DCA 를 거친 거래에서는 마지막 단계
> 이후의 고점만 반영된다. 즉 역산값은 **실제 MFE 의 하한선**이고, 실제로 놓친
> 수익은 그보다 크다. 리포트에서 `추정` 으로 따로 표시된다.

모의투자 기록은 슬리피지·체결 실패·마진 부족이 없어 **실제보다 좋게 나온다.**
리포트의 `출처별` 표에서 분리해 볼 수 있다.

### 변경 제안 (`evolve.py`)

```bash
python evolve.py            # 제안 출력 + proposals/ 에 저장
python evolve.py --stdout   # 출력만
```

`config.py` 를 **절대 수정하지 않는다.** 근거·표본 수·부작용을 붙인 변경안만 낸다.
가드레일: 전체 표본 30건 미만이면 제안 자체를 하지 않고, 근거 부분집합이 10건
미만이면 `저신뢰` 로 표시하며, 1회 변경폭은 현재값의 30% 로 제한한다.

과거 봇들에서 손절 한도가 하루에 세 번 바뀐 이력이 있다 (`LESSONS.md` 참고).
가드레일은 그 재발을 막기 위한 것이다.

> 손절 스캔은 **근사치**다. 조기 손절 시 사라졌을 이후의 DCA·회복분을 반영하지
> 않으므로 값 자체가 아니라 방향만 참고할 것. 표본 수십 건 미만에서는 우연을
> 규칙으로 오인하기 쉽다.

## 실거래 안전장치

- **리스크 거버너** (`risk_governor.py`) — 전략 위에 앉아 "지금 얼마를 걸어도
  되는가"만 판단한다. 진입 여부·코인 선택·청산 타이밍에는 관여하지 않고,
  **보유 중인 포지션도 건드리지 않는다** (손절 한도는 진입 당시 시드 기준 고정).

  | 브레이크 | 발동 | 조치 |
  |---|---|---|
  | 고점 대비 낙폭 | -6% / -10% / -15% | 시드 80% / 60% / 35% |
  | | **-20%** | **신규 진입 2시간 중지** |
  | 연속 손실 | 2회 / 3회 | 시드 65% / 40% |
  | | **4회** | **신규 진입 2시간 중지** |
  | 당일 수익 반납 | 당일 고점 수익의 45% 반납 | **4시간 중지** (익일 자동 해제) |

  세 브레이크 중 가장 강한 것이 적용되며, 익절 1회로 연속손실 카운터는 즉시 리셋된다.
  고점·카운터는 `governor_state.json` 에 저장돼 재시작해도 풀리지 않는다.

  **정지에서 빠져나오는 법** — 정지 시간이 끝나면 조건이 아직 살아 있어도
  시드 25%(`GOVERNOR_RECOVERY_MULT`)로 재개한다. 그러지 않으면 진입이 막혀
  이길 기회가 없고, 이기지 못하니 조건이 영영 안 풀리는 **데드락**이 된다.
  재개 후 또 지면 다시 정지하고, 익절 1회로 시드 100% 복귀한다.

  근거: `gateio_90win` 은 $100 → $518(3일) → $234(2일)를 겪었다. 이 장치가
  있었다면 $466에서 시드 60%, $440에서 35%, $414에서 매매가 멈췄다 (`LESSONS.md`).
  관련 설정: `GOVERNOR_*` (config.py) / 끄려면 `GOVERNOR_ENABLED = False`

- **수익 보존 락** (`PROFIT_LOCK_*`) — 손에 쥘 수 있었던 수익을 되돌려주지 않는다.
  고점 순수익(청산 비용까지 차감)이 $3 이상 찍히면, 그 절반 아래로 떨어지는
  순간 즉시 확정 청산한다.

  왜 필요한가 — DCA 단계에서는 고정 익절이 꺼져 있고 트레일만 남는데,
  트레일 되돌림 거리의 하한 `DCA_TRAIL_DIST_MIN = 0.003`(코인 0.3%)이
  8배 레버리지에서 **포지션 2.4%포인트**다. 비례 공식(수익 × 25%)이 이 하한을
  넘으려면 수익이 9.6% 여야 하므로, 그 아래에서는 항상 2.4%포인트를 고정 반납한다.

  | 고점(포지션) | 청산 | $240 기준 순손익 |
  |---|---|---|
  | +2.0% | −0.4% | −$4.81 |
  | +4.0% | +1.6% | −$0.03 |
  | +6.0% | +3.6% | +$4.76 |

  즉 고점이 +4% 를 넘지 않으면 트레일 익절은 **구조적으로 이익을 낼 수 없다.**
  실측: 2단계 $240 에서 순수익 $6 고점 → 트레일 청산 $0.21. 락 적용 시 $3.00.

  발동 시점에 반드시 이익이므로 이 규칙은 **손실을 만들 수 없다.** 수익 9.6%
  이상 구간에서는 기존 트레일이 더 타이트해져 락보다 먼저 잡으므로, 락은
  트레일이 무력한 저수익 구간만 메운다.

- **거래소 강제 손절 백스톱** — 진입·DCA 직후 BingX 서버에 `STOP_MARKET` 배치.
  봇 프로세스가 죽거나 회선이 끊겨도 거래소가 직접 손절을 집행한다.
  정상 상황에선 봇 자체 손절(-$240)이 먼저 발동하므로 체결되지 않는다.
  주문 실패는 매매를 막지 않고 `WARNING`만 남긴다 (봇 손절은 계속 작동).

  | 단계 | 투입 | 명목 | STOP 거리 | 그때 손실 | 자본 대비 |
  |---|---|---|---|---|---|
  | 0 | $60 | $480 | -8.0% | -$38 | 3.7% |
  | 1 | $120 | $960 | -8.0% | -$77 | 7.3% |
  | 2 | $240 | $1,920 | -8.0% | -$154 | 14.6% |
  | 3 | $480 | $3,840 | -8.0% | -$307 | 29.2% |
  | 4 | $960 | $7,680 | -4.7% | -$360 | 34.3% |

  4단계 청산(liquidation) 예상 지점이 코인 -12% 부근이므로 백스톱이 확실히 앞선다.
  관련 설정: `EXCHANGE_STOP_*` (config.py)

- **거래소 정합성 점검 (60초 주기)** — 백스톱이 체결되면 거래소 포지션만 사라지고
  봇은 계속 보유 중이라고 믿는다. 유령 포지션을 붙잡고 있으면 신규 진입도 못 하므로,
  보유 중일 때 주기적으로 거래소와 대조해 불일치를 감지하면 장부를 닫는다.
  체결가를 알 수 없으므로 걸어뒀던 STOP 가격을 추정치로 쓰며, `CRITICAL` 로그로
  거래소 내역과 대조하라고 알린다. 조회 실패는 "포지션 없음"으로 오판하지 않는다.

- **장부 대조 (30분 주기, 포지션 없을 때만)** — 체결가를 거래소에서 받아오지 않고
  `_apply_slip()` 으로 **추정**하기 때문에, 봇 장부의 `total_pnl` 은 실제 손익과
  조금씩 어긋나고 거래가 쌓일수록 오차가 누적된다. 봇이 "-$20" 이라고 해도 실제
  계좌는 다를 수 있다. 포지션이 없을 때(미실현 손익 없음) 거래소 순자산과 대조해
  차이를 로그로 남기고, `LEDGER_DRIFT_WARN_USD`($5) 이상 벌어지면 `WARNING`.
  **거래소 값이 진실이다** — 차이가 커지면 `TOTAL_CAPITAL` 을 실제 잔고로 맞출 것.

- **진입 전 미청산 포지션 검사** — 거래소에 남은 포지션이 있으면 신규 진입 차단
- **주문 실패 시 장부 미반영** — 진입 주문 거부되면 내부 상태를 만들지 않음
- **청산 실패 시 상태 유지 + CRITICAL 로그** — 포지션을 잃어버리지 않도록 IDLE 전환 금지
- **부분 DCA** — 가용 마진이 계획 금액보다 적으면 마진의 90%까지만 투입
- **워치독 뮤텍스 분리** (`BingX_Phoenix_Live_v1`) — 페이퍼 봇 인스턴스와 충돌 방지

## 주의

- `.env`(API 키), `state.json`, `trades.jsonl`, `governor_state.json`, `*.log`는 `.gitignore`로 제외된다. 커밋하지 말 것.
- BingX **헤지 모드**(LONG/SHORT 동시 보유) 계정 설정이 필요하다.
- 실제 자금이 움직인다. 파라미터 변경 후에는 반드시 `close_all.py` 사용법을 먼저 확인할 것.
